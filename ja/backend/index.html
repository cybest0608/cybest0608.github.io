MiraiChat バックエンドカスタマイズガイド

MiraiChat バックエンドカスタマイズガイド

Language / 言語 / 语言 / 語言: English · 日本語 · 简体中文 · 繁體中文

このガイドは、Python や Docker、簡単なサーバー設定はできるけれど、バックエンド専門ではない方向けです。

MiraiChat は、少しずつ自分の運用に合わせて調整できるように設計されています。

なぜ MiraiChat はカスタムバックエンドをサポートするのか

MiraiChat はプライバシー重視ですが、必要な運用ポリシーは利用者ごとに異なります。

  • データを完全に自分で管理したい
  • 地域やネットワーク事情に合わせて通信を調整したい
  • 自分の自動化や社内ワークフローと連携したい

カスタムバックエンドを使うと、同じアプリ体験を維持しながら、

  • データ保存先
  • メッセージの配送方式
  • セキュリティ・保持ポリシー
  • 独自拡張の範囲

を自分で決められます。

実際にカスタマイズできる項目

すべてを書き換える必要はありません。1つずつ始めれば十分です。

1) メッセージ配送とルーティング

調整できる内容:

  • オンライン配送の優先順
  • クロスノード fanout の挙動
  • オフラインキュー戦略
  • マルチデバイス同期ルール

効果: レイテンシと配信信頼性を運用に合わせて最適化できます。

2) 認証とセッションポリシー

調整できる内容:

  • セッション有効期限
  • 登録方式（オープン/キー必須）
  • 管理者保護ルール
  • トークン検証の厳格度

効果: プライベート運用の強化、または信頼ネットワーク向け簡易導入が可能です。

3) WebSocket イベント処理

調整できる内容:

  • 受け付けるイベント種別
  • バリデーションロジック
  • イベントごとの配送制御
  • 既読/削除/システム通知の扱い

効果: 独自機能向けのイベントを追加しやすくなります。

4) プッシュ通知の挙動

調整できる内容:

  • どのメッセージで push を送るか
  • 同期/非同期の送信方針
  • プロバイダの優先順とフォールバック
  • ハブ/プライベート構成での relay 動作

効果: 電池・回線コストと通知品質のバランス調整ができます。

5) ストレージと保持ポリシー

調整できる内容:

  • ユーザー/メディア容量制限
  • ファイル保持日数
  • オフラインメッセージ保持
  • クリーンアップ実行ルール

効果: 低保持のプライバシー重視運用から、大きめの自己ホストまで対応可能です。

6) インフラ構成（単一ノードから拡張）

調整できる内容:

  • SQLite 中心のシンプル運用
  • presence/fanout の memory/Redis 切り替え
  • 将来のスケール向け移行導線

効果: まず小さく始めて、必要になってから拡張できます。

自前バックエンド運用のメリット

  • データ主権: サーバー、DB、保持期間を自分で管理
  • 地域最適化: 回線事情に合わせた設定
  • 開発速度: 変更してすぐ検証できる
  • 連携自由度: 独自 API、認証、モデレーション、自動化に接続可能
  • ベンダーロックイン回避: 運用方針を自分で選べる

WebSocket 直結モードとトンネルモード

ネットワーク条件が利用者ごとに違うため、MiraiChat は両方をサポートします。

直結モード (WS_CONNECTION_MODE=direct)

安定した公開エンドポイントを持てる場合に適しています。

  • 多くの環境で低レイテンシ
  • 経路が短く予測しやすい
  • 高速性を重視する構成に向く

トンネルモード (WS_CONNECTION_MODE=tunnel)

公開受信ポートを用意しにくい場合に適しています。

  • 厳しい NAT や家庭回線でも到達しやすい
  • 自己ホストでの公開が比較的簡単
  • 直結より少し遅延が増えることがある

速度最優先なら direct、導入しやすさ重視なら tunnel が目安です。

初めての人向けおすすめ手順

  1. まず既定設定で安定動作を確認
  2. 小さな endpoint か WS イベントを 1 つ追加
  3. 保持ポリシーを 1 項目だけ調整
  4. 必要になった時点で Redis fanout を導入

さいごに

バックエンド専門家でなくても問題ありません。

小さな変更から始めて、ローカルで試し、少しずつ自分の運用へ育てていきましょう。
