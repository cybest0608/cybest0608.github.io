MiraiChat 暗号化技術リファレンス

Language / 言語 / 语言 / 語言: English · 日本語 · 简体中文 · 繁體中文

範囲

本文書は、クライアントのコードベースに現在実装されている暗号化設計の概要をまとめたものです。

1. コアプリミティブ

  • 非対称鍵共有: X25519
  • 非対称署名: Ed25519
  • 対称 AEAD: AES-GCM-256
  • PIN KDF: PBKDF2(HMAC-SHA256, iterations=600000, bits=256)
  • ラチェット KDF コンポーネント: HMAC-SHA256

関連する実装:

  • lib/key_manager.dart

2. ID およびデバイス鍵資料

KeyManager.init(username, pin) は、PBKDF2 を使用してユーザー PIN + ユーザー名ソルトから決定論的なベースシードを派生させます。その後、2 つの決定論的シードが以下のように分割されます。

  • 暗号化鍵ペアシード (X25519)
  • ID 署名鍵ペアシード (Ed25519)

影響:

  • 鍵ペアは、同じユーザー名/PIN 入力から再現可能です。
  • セキュリティ強度は、PIN のエントロピー + PBKDF2 の計算量に依存します。

3. 1:1 メッセージ暗号化フロー

ダイレクトメッセージの場合:

  1. クライアントは、相手の公開鍵 (X25519) を使用して共有シークレットを派生させます。
  2. プライマリパス（メインデバイス）: メッセージごとのラチェット鍵が派生され、更新されます。
  3. 互換パス（サブ/非ラチェットモード）: 固定の共有シークレットが使用されます。
  4. メッセージペイロードは enc:<base64-aesgcm-box> として暗号化されます。

ラチェットの動作:

  • ラチェット状態: 会話ごとに ratchet + counter が保持されます。
  • メッセージ鍵と次のラチェット状態は、HMAC-SHA256 ドメイン分離ラベルを介して派生されます。
  • 状態は更新後にセキュアストレージに永続化されます。

関連する実装:

  • lib/outgoing_message_queue.dart
  • lib/incoming_message_handler.dart
  • lib/key_manager.dart

4. グループメッセージ暗号化

  • グループ鍵は対称鍵であり、AES-GCM シークレットキージェネレーターを介して生成されます。
  • グループコンテンツはグループ鍵 (AES-GCM-256) で暗号化されます。
  • メンバーシップの変更時にグループ鍵の更新/ローテーションをトリガーできます。
  • メンバーへの配布は、メンバーごとの共有シークレット暗号化を使用してラップされます。

関連する実装:

  • lib/incoming_message_handler.dart (_rotateGroupKeyAfterMembershipChange)
  • lib/key_manager.dart (generateGroupKey)

5. シールドセンダー (Sealed Sender) パス

送信される 1:1 メッセージは、以下の内容を含むシールドエンベロープ（密封された封筒）にラップされる場合があります。

  • sealed_payload = 暗号化された内部エンベロープ
  • サーバーからの sender_certificate
  • protocol_version = 1

受信側による検証:

  1. サーバー署名鍵による証明書の形式と署名 (Ed25519) の検証。
  2. 証明書の有効期限。
  3. 共有シークレットによるシールドペイロードの復号。

関連する実装:

  • lib/outgoing_message_queue.dart (シールドセンダーの構築)
  • lib/incoming_message_handler.dart (_handleSealedSender)
  • lib/certificate_pinning_manager.dart (サーバー署名鍵 + ピンリスト検証)

6. 転送と信頼モデル

  • API/WebSocket 通信には HTTPS/WSS 転送を使用します。
  • 証明書ピンニングマネージャーのサポート:
    • ハードコードされた公式ピン
    • 制限付きのカスタムピン信頼履歴
    • Ed25519 検証付きの署名済みピンリストのインポート
  • 信頼監査イベントとローテーションメタデータはプリファレンスに記録されます。

関連する実装:

  • lib/chat_api.dart
  • lib/websocket_connection_manager.dart
  • lib/certificate_pinning_manager.dart

7. ローカルシークレットストレージ

シークレットはプラットフォームのセキュアストレージを介して保存されます。

  • iOS Keychain
  • Android 暗号化セキュアストレージ

保存される機密アイテムには、セッションシークレット、認証シークレット、リカバリシード、ラチェット状態が含まれます。

関連する実装:

  • lib/secure_storage.dart

8. 現在の重要なセキュリティ上の注意

  • LocalMessageStore.decryptContent は現在入力をそのまま返します。ローカルメッセージ DB の保護は、この関数によるフルコンテンツ暗号化ではありません (lib/local_message_store.dart)。
  • ユーザー名 API ハッシュは、グローバルな定数ソルトを使用した多段の SHA-256 を使用します。これはルックアッププロトコルのための難読化/派生動作であり、パスワード KDF の代替ではありません。
  • PIN からの決定論的な鍵生成は運用上便利ですが、最高のセキュリティのためには強力な PIN ポリシーが必要です。

9. 脅威への対応（現在）

対応済み:

  • 受動的なネットワーク傍受 (TLS + E2EE ペイロード)
  • サーバー証明書の不一致/改ざん検出 (ピンニング)
  • 送信者証明書の改ざん (署名検証)
  • 転送中のメッセージの機密性/整合性 (AES-GCM)

一部対応 / 設計依存:

  • デバイスの侵害（OS のハードニングおよびアプリロックポリシーに依存）
  • 脆弱なユーザー PIN の選択（PBKDF2 はブルートフォースを遅らせますが、低いエントロピーを修正することはできません）
  • メタデータのプライバシー（ルーティングメタデータはプロトコルの必要性から依然として存在します）
