MiraiChat 後端自訂指南

Publish Date:   2026-03-27

MiraiChat 後端自訂指南

Language / 言語 / 语言 / 語言: English · 日本語 · 简体中文 · 繁體中文

這份指南面向有一定實作能力的使用者：會使用 Python、Docker，也能做基本伺服器設定，但不一定是專職後端工程師。

MiraiChat 的後端就是為這種可逐步調整的使用情境而設計。

為什麼 MiraiChat 支援自訂後端

MiraiChat 以隱私優先為核心，但每位使用者的部署需求不同。

  • 有人希望資料完全由自己掌控
  • 有人需要依區域與網路條件調整策略
  • 有人想串接自家的自動化、審核或內部服務

自訂後端的價值在於：在不改變整體 App 體驗的前提下，你可以自行決定

  • 資料儲存位置
  • 訊息路由方式
  • 安全與保存政策
  • 想新增的功能範圍

可以自訂哪些後端能力

不需要一次改完整套系統，從單一模組開始即可。

1) 訊息路由與投遞策略

可調整：

  • 線上投遞優先順序
  • 跨節點 fanout 行為
  • 離線佇列策略
  • 多裝置自同步規則

效益：更容易平衡延遲、可靠度與多裝置體驗。

2) 驗證與工作階段策略

可調整：

  • 工作階段過期規則
  • 註冊模式（開放或註冊碼）
  • 管理端保護政策
  • token 驗證嚴格度

效益：可建立更嚴謹的私有部署，或更順暢的可信網路導入流程。

3) WebSocket 事件處理流程

可調整：

  • 允許的事件型別
  • 事件驗證邏輯
  • 各事件的路由策略
  • 已讀/刪除/系統事件處理方式

效益：可快速加入符合自家需求的新事件型別。

4) 推播通知策略

可調整：

  • 哪些訊息類型觸發推播
  • 同步/非同步送出策略
  • 推播通道優先順序與回退路徑
  • hub/私服拓撲中的 relay 行為

效益：在電量、網路成本與觸達率之間取得更合適的平衡。

5) 儲存與保存策略

可調整：

  • 使用者/媒體容量上限
  • 檔案保存天數
  • 離線訊息保存策略
  • 清理排程規則

效益：可從低保存隱私模式，擴展到較大型自託管歸檔。

6) 基礎設施路徑（單機到多節點）

可調整：

  • 以 SQLite 快速起步
  • memory/Redis 的 presence 與 fanout 切換
  • 後續擴充遷移路徑

效益：先上線，再依需求擴充，維運成本更可控。

自建後端帶來的實際好處

  • 資料主權：伺服器、資料庫、保存規則由你決定
  • 在地化優化：依你的區域網路現實做調整
  • 迭代速度快：修改後可立即驗證
  • 整合自由：可接自家 API、身分系統、自動化與審核流程
  • 不被固定廠商綁定：模型與流程可持續演進

WebSocket 直連模式 vs 隧道模式

MiraiChat 同時支援兩種模式，因為實際網路環境差異很大。

直連模式 (WS_CONNECTION_MODE=direct)

適合情境：你可以提供穩定的公網入口。

  • 通常延遲更低
  • 路徑更短且可預期
  • 適合追求效能上限

隧道模式 (WS_CONNECTION_MODE=tunnel)

適合情境：不方便直接暴露公網入站連線。

  • 適合嚴格 NAT 或家庭網路
  • 自託管遠端可達性通常更容易
  • 相較直連一般會增加少量延遲

簡單建議：重視最低延遲用 direct，重視部署便利用 tunnel。

建議的第一步改造路徑

  1. 先以預設驗證/工作階段策略跑通基線
  2. 新增一個小型 endpoint 或一個 WS 事件
  3. 只調整一項保存政策並觀察運行狀況
  4. 當單節點出現瓶頸時再導入 Redis fanout

給實作者的一句話

你不需要是後端專家，也能把 MiraiChat 後端調整成真正適合自己的樣子。

從小改動開始，持續測試與迭代，就能很快看到成果。
